## 1. Что это за проект

**Rep Legends** — фитнес-игра в Telegram (Mini App). Камера телефона распознаёт позу и считает упражнения: отжимания, подтягивания, приседания, пресс (подъёмы корпуса). Повторения превращаются в игровые действия: дуэли 1 на 1, прокачка героя, ранги E–S, боссы, соревнования в группах. Вдохновлено мобильной игрой PushArena (но 4 упражнения и своё оформление).

- Аудитория: широкая. Языки: русский и английский (по умолчанию из Telegram, есть переключатель).
- Видео обрабатывается **только на устройстве** и никуда не отправляется.
- Монетизация пока не делается, но архитектура готова к Telegram Stars (косметика).

- **Токен бота никогда не просить в чат и не класть в код** — только в `.env` (он в .gitignore).

- Пользователь проверяет на телефоне сам; после выкладки просить закрыть и заново открыть игру в Telegram.

## 3а. Прогресс и сохранения (КРИТИЧНО — пользователь просил сделать качественно)

- Код: `src/progress/progress.ts` (чистая логика + 35 тестов `progress.test.ts`), `src/progress/store.ts` (хранение, хук `useProgress`).
- **Две копии**: `localStorage rl.progress` (+ `rl.progress.bak` — предыдущее сохранение) и **Telegram CloudStorage** ключ `progress` (Bot API 6.9+, ≤ 4096 символов; переживает очистку данных, смену телефона и смену адреса сайта). Вне Telegram — только телефон.
- **Модель «только растёт»**: опыт и итоги хранятся **по устройствам** (`dev[<deviceId>]`, id случайный в `rl.deviceId`), реальное значение = сумма по устройствам; объединение = максимум по каждому устройству и каждому полю; рекорды = максимум. Поэтому: опыт с двух телефонов складывается, старая/испорченная копия ничего не уменьшает, порядок синхронизаций не важен.
- Всё прочитанное идёт через `sanitize` (мусор → 0, плохие ключи отбрасываются). Испорченная локальная копия → backup → облако.
- **Синхронизация**: при запуске (локальная + старые рекорды `rl.best.*` + облако), при возвращении в приложение, после каждого подхода. `recordSet` сохраняет на телефон **мгновенно**, облако — следом; экран результата показывает «☁️ сохранено в облаке» / «📱 на телефоне».
- **Миграция**: старые ключи `rl.best.pushup`, `rl.best.pullup` (до сложностей → `pullup.medium`), `rl.best.pullup.<d>` подхватываются автоматически (так «вернулся» потерянный рекорд). За найденные старые рекорды начисляется **разовый опыт** (рекорд × опыт за повторение) под фиксированным псевдо-устройством legacybonus — из-за merge по максимуму он не задваивается при перезапусках и на других телефонах.
- **Статы**: Атака ← отжимания (1 опыт / повторение), Сила ← подтягивания (2 / 3 / 4 опыта за очко на лёгком / среднем / тяжёлом), Выносливость ← приседания (1 опыт / присед), Защита ← пресс (1 опыт / подъём корпуса, счётчик `absReps`). Уровень стата: до след. уровня **10, 15, 20, 25…** опыта (+5 за уровень, решение пользователя 2026-11-15). Уровень **игрока/героя** = от суммы опыта: **50, 75, 100…** (пользователь просил менять только статы — не трогать) Ранг пока всегда E.
- Не сохраняется: незавершённый подход (если закрыть приложение посреди подхода). Настройки и выбор сложности — только в `localStorage` (это предпочтения, не прогресс).
- Не трогать формат без миграции; версия — `PROGRESS_VERSION`.

## 8. Как устроен счётчик отжиманий

- Камера сбоку, телефон вертикально на полу, 2–2,5 м. Front-камера по умолчанию (картинка зеркалится).
- Берётся сторона тела с лучшей видимостью; углы считаются **в пикселях** (не в нормализованных координатах).
- Пороги (`PUSHUP_RULES`): низ < 90°, верх > 155°, начало попытки < 140°, линия плечо–таз–лодыжка ≥ 150°, корпус горизонтален (dx > 1,3·dy), видимость ≥ 0,6, сглаживание EMA α=0,4, **minRepMs 400** (считается от момента, когда руки перестали быть прямыми).
- Подсказки: «Ниже!», «Спину ровнее!», «Слишком быстро!», «Прими упор лёжа», «Тебя не видно».
- Экран: setup → loading → calibrating (1 с в позе) → 3-2-1 → active → result (рекорд в `rl.best.pushup`). Отладка: скелет + `FPS · GPU/CPU · сторона`, углы.
- Каждое засчитанное повторение пишется в `counter.log` (`RepRecord`) — пригодится для серверного античита.

### Как устроены упражнения (общий каркас)
- Каждое упражнение = арена = файл в `src/exercises/` с `ExerciseDef`: `measure` (кадр → BaseFrame с `visible/points/lines/debug`), `calibrationHint` ('hold' = готов), `createCounter`, `holdMs`, `countdown` (0 = старт сразу), опционально `inPosition` + `autoFinishMs` (автозавершение).
- Экран `Workout.tsx` один на все упражнения; тексты — `t.exercises[id]` (`name`, `setup[]`, `calibrate{}`, `hints{}`), рекорд — `rl.best.<id>`.
- Новое упражнение: файл + тесты → регистрация в `exercises/index.ts` (EXERCISES + ARENAS playable) → тексты ru/en → картинка в `SetupArt.tsx`.

### Счётчик приседаний (`squat.ts`, этап 3)
- Как отжимания: правила → калибровка (1 с стоя) → 3-2-1 → подсчёт → результат. Телефон вертикально на полу в 2–3 м, человек **боком или вполоборота** (спереди сгиб колена в 2D почти не виден). Нужно всё тело: плечо, таз, колено, **лодыжка** (visibility ≥ 0,6, берётся лучше видимая сторона).
- «Оптимально-средняя» техника (решение пользователя 2026-11-24, не строго). **Два независимых признака** (после реального теста: один угол колена сбоку слишком шумный — пропуски, двойной счёт, засчитывались мини-приседы):
  - угол колена **одной зафиксированной ноги** (смена ноги только если другая видна лучше на 0,15 в течение 8 кадров);
  - **опускание таза** `drop = 1 − (лодыжки−таз)/(то же стоя)`; рост «стоя» запоминается только стоя (быстро вверх, вниз — лишь в пределах 2%, иначе медленный мини-присед «съедался»).
  - Низ: (колено < 115° И drop ≥ 0,2) ИЛИ drop ≥ 0,3 (для съёмки вполоборота). Встал: колено > 150° И drop < 0,12. Попытка началась: drop > 0,045 (≈4 см). «Чуть ниже!»: попытка была, но таз вернулся (drop < 0,0225) без низа. Каждое изменение держится **3 кадра** (debounce). После повторения пауза 200 мс.
  - Наклон корпуса **≤ 65°**, minRepMs **500**, EMA колена 0,5, EMA опускания таза 0,6.
  - **Точность (2026-11-24, после 20 из 22 на телефоне):** «встал» = таз вернулся (drop ≤ 0,15) и колено > 135° — уставший спортсмен не выпрямляется полностью. Попытка и «Чуть ниже!» меряются от **уровня стойки** (est: медленное среднее положения таза между повторениями; ниже — только если держится 0,3 с, берётся среднее за этот период). Рост в стойке = **среднее** первой секунды (без кадров ниже 1%), потом только подтверждённое «выпрямился выше». Попытка: таз ниже уровня стойки на > 0,03 дольше 100 мс; «Чуть ниже!» только если опустился ≥ 0,035 (~3 см), иначе это дрожание. Низ/верх держатся 2 кадра, начало/возврат — 3 кадра/100 мс.
  - **Стресс-тест** squat.stress.test.ts: 361 случайный подход (10–40 повторений, 1 подход на 100), разный темп и глубина, неполное выпрямление от усталости, паузы, дрожание точек и сбои, 15–30 fps с неровными кадрами. Требование: **счёт точный в каждом подходе** (сейчас 361/361); лишние подсказки ≤ 1 на 200 повторений (сейчас 0 / 1 на ~1000 / 1 на ~275 для хорошего / среднего / слабого телефона).
  - **«Стой на месте»**: опорная точка (лодыжки x, рост в кадре) запоминается в начале; сдвиг стоп > 0,35 роста или изменение размера > 20% → пауза + плашка «Вернись на место перед камерой» (`hint 'place'`, в Workout — постоянная плашка как 'lost', без звука на каждый кадр); простоял на новом месте 2,5 с → новое место принято.
- Калибровка: `notVisible` → `turnSide` (стоит лицом: разнос тазобедренных / длина корпуса > 0,45) → `standUp` (колено ≤ 160° или наклон > 30°) → `hold`.
- Подсказки: «Чуть ниже!» (полуприсед / мини-присед), «Спину ровнее, грудь вперёд!» (наклон > 65° — не засчитано), «Слишком быстро! Плавнее» (пружинка), «Тебя не видно», «Вернись на место перед камерой».

### Счётчик пресса (`abs.ts`, этап «4» у пользователя = 3б в плане)
- Подъёмы корпуса (sit-ups). Телефон вертикально на полу в 2–3 м, человек лежит на спине **боком**, колени согнуты. Нужны плечо, таз, колено (visibility ≥ 0,5); лодыжка — только для проверки «колени согнуты».
- Метрика: **угол корпуса к полу** (линия плечо–таз, в пикселях) **одной зафиксированной стороны**, отсчёт от направления «от коленей»: 0° лёжа, 90° сидя, **> 90° — наклон к коленям** (раньше бралось |dx| и «локти к коленям» выглядело как опускание → ложные «Ложись до пола!», найдено пользователем 2026-11-25) (смена — если другая лучше на 0,15 в течение 8 кадров). EMA 0,5.
- «Оптимально-средняя» техника: в инструкции «примерно до половины пути / ≈ 60°», засчитывается от **55°** (5° запаса на дрожание — без него стресс-тест терял повторения на слабом телефоне). Касаться коленей не нужно.
- **Уровень лёжа** (rest): медленное среднее (пока лежит — может и подниматься); ниже — только если держится 0,3 с (среднее за период). Низ = угол ≤ max(25°, rest + 10°), 2 кадра → «заряжено»; на слабом телефоне учитывается и «сырой» угол (если сглаженный рядом, ≤ +15°).
- Верх (≥ 55°, 2 кадра): не было «лёг» → «Ложись до пола!» (если с верха опустился ниже 42° и поднялся снова без касания пола); подъём от последнего устойчивого кадра «лёжа» < 80 мс или верх→верх < 700 мс → «Слишком быстро! Плавнее»; иначе повторение **ждёт подтверждения**: +1, когда начал опускаться (< 42°) или просидел вверху 2 с на месте; если таз поднялся > 0,35 длины корпуса (встаёт, чтобы взять телефон) — отменено (найдено пользователем: 4 подъёма → 5).
- **Обе ноги согнуты**: по каждому кадру берётся самое прямое видимое колено (обе стороны); если с прошлого верха ≥ 50% кадров колено > 150° → не засчитано, «Согни обе ноги в коленях!» (`knees`). Калибровка тоже проверяет обе ноги. Невидимая дальняя нога не мешает.
- Попытка: выше rest на 12° дольше 100 мс; вернулся (ниже rest + 6°, 3 кадра) без верха → «Выше!», если поднялся ≥ 18° над rest, иначе тишина (кивок головой). Пауза 200 мс после повторения.
- «Вернись на место»: сдвиг таза > 0,6 длины корпуса или размер ±25% → пауза, плашка; лежит на новом месте 2,5 с → принято.
- Калибровка: `notVisible` → `lieDown` (корпус > 30°) → `bendKnees` (любое видимое колено > 150°) → `hold` (1 с) → 3-2-1.
- Стресс-тест abs.stress.test.ts: 361 подход (10–40 повторений + 1 на 100), усталость (ниже верх, медленнее, голова не до пола), паузы, шум, сбои, 15–30 fps — **счёт точный в 361/361** (9 137 повторений), лишних подсказок 0 / 2 / 4 на ~3000 (хороший / средний / слабый телефон). В симуляции также «локти к коленям» (верх 100–125°) у трети людей и шум/сбои положения ног.
- Опыт: Защита, 1 за повторение. Картинка установки — `AbsArt` в SetupArt.tsx.

### Счётчик подтягиваний (`pullup.ts`)
- Камера снизу, телефон на полу в 2–3 м от турника, прислонён, смотрит вверх. Человек может висеть **лицом ИЛИ спиной** к камере (у многих турник у стены). **Обязательны только плечи, локти, кисти** (СРЕДНЯЯ visibility ≥ 0,3 — со спины согнутые руки у перекладины получают низкую уверенность); лицо и ноги/стопы не нужны («захват на доверии» — решение пользователя 2026-11-15).
- Метрики (в ширинах плеч): средний угол локтей; «висит» = кисти выше плеч ≥ 0,1 (маленький порог — вверху плечи подходят к перекладине на 0,3–0,5); `barScore` = max(сигнал подбородка, сигнал плеч):
  - плечи (любой ракурс): `0,55 − (плечи − кисти)` — в мёртвом висе ≈ −1, вверху ≥ 0;
  - подбородок (только если лицо видно, нос+рот ≥ 0,6): `(кисти − подбородок) + 0,12`, подбородок = рот + 0,9·(рот−нос).
- Повторение засчитывается **вверху** (`barScore ≥ 0`), только если перед этим был **полный вис** (локти ≥ 145°; реальный вис на телефоне ≈ 157°).
- Автозавершение — только при **уверенном** «руки ниже плеч» (`inPosition = !visible || hanging`): сомнительный кадр подход не заканчивает. minRepMs **150** (только фаза подъёма, ≈4 кадра при 28 fps). EMA α=**0,7** (лёгкое); «руки прямые внизу» проверяется и по мгновенному углу — при быстром темпе прямые руки лишь на 1–2 кадра. «Ушёл от перекладины» = barScore < −0,3.
- В отладке: `elbow … · bar ±… · face/back · hang/off bar`. В журнале повторения пишется `barScore` и `faceVisible`.
- Подсказки: «Подбородок выше перекладины!» (тянул, но не дотянул), «Выпрямляй руки внизу!» (подтянулся без полного виса), «Слишком быстро!», «Тебя не видно».
- Старт **без 3-2-1**: повис на прямых руках 0,6 с → сразу «GO». **Автозавершение**: не на турнике 3 с → результат (баннер «Подход завершится через N…»).
- **Три сложности** (решение пользователя 2026-11-15), экран `screens/PullupDifficulty.tsx` после нажатия «Подтягивания» в аренах, у каждой описание; выбор и резинка запоминаются (`rl.pullup.options`); рекорд у каждой сложности свой (`rl.best.pullup.<easy|medium|hard>`), на карточке арены — лучший из трёх.

  | | Лёгкий | Средний | Тяжёлый |
  |---|---|---|---|
  | вис (локти ≥) | 130° | 145° | 155° |
  | подбородок: допуск / плечи до перекладины | 0,2 / 0,65 | 0,12 / 0,55 | 0 / 0,45 |
  | раскачка | 1 | 0,5 | 0 («Без раскачки! Не засчитано») |
  | резинка | 1 | 0,5 | запрещена (переключатель выключен) |

- **Резинку камера не видит** → переключатель «Подтягиваюсь с резинкой» (на доверии). **Раскачка определяется автоматически** (примерно): размах наклона корпуса в 3D (`worldLandmarks`) > 25°, ИЛИ угол плечо–таз–колено < 140° (колени к груди), ИЛИ боковое смещение таза > 0,5 ш.пл. — за окно 1,5 с до верхней точки (начиная с виса после предыдущего повторения). Нужны видимые таз/колени; если их нет — раскачка не оценивается (засчитывается как чистое). Пороги стартовые — подстраивать по отладке (вторая строка `swing: pitch … · hips … · sway …`).
- Очки могут быть дробными (7.5); в результате — разбивка «Чистых / С раскачкой / С резинкой».
- ⚠️ Самое рискованное упражнение для камеры. Если на практике ненадёжно — запасной план: Accelerometer Telegram (телефон в кармане), без рейтинга.
